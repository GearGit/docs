Conditional visibility, also called display logic, lets you show or hide a question, an individual answer option, or a row in a grid depending on what a respondent answered earlier. This page explains how display logic works, how it differs from branching, and how to set up a visibility rule.

## Display Logic vs. Branching

It helps to understand the difference between these two tools before you build:

- **Display logic** controls whether an element is visible on the page. A hidden question is simply not shown; the respondent stays on the same path through the survey.
- **Branching** routes the respondent to a completely different question or block, skipping everything in between.

Use display logic when you want to show a follow-up on the same page or keep the survey flow linear while tailoring the content. Use branching when you want to skip ahead several questions or send respondents down entirely different tracks.

## What You Can Show or Hide

Display logic can be applied to three types of elements:

- **A whole question:** The question appears or disappears based on a condition.
- **An individual answer option:** A specific choice within a question is shown or hidden.
- **A row in a grid:** A single row in a grid question is shown or hidden.

## Adding a Display Logic Rule

<Steps>
  <Step title="Select the element to control">
    In the survey builder, click the question, option, or grid row you want to show or hide. Open the **Logic** tab in the right-hand panel.

    ![A question selected in the builder canvas with the Logic tab open on the right](/images/placeholder.png)
  </Step>

  <Step title="Enable display logic">
    Find the **Visibility** section and toggle it on. The default state is **Always show**. Turning on the toggle switches the element to conditional visibility.

    ![The Visibility toggle switched on, revealing condition fields below it](/images/placeholder.png)
  </Step>

  <Step title="Choose the source question">
    In the **If** dropdown, select the earlier question whose answer will drive the visibility. Only questions that appear before the current element are available.
  </Step>

  <Step title="Set the condition">
    Choose a condition from the **Condition** dropdown, for example "is equal to," and then select or type the value to match. For example: If Q3 is equal to "Yes."

    ![The condition row reading: If Q3 is equal to Yes](/images/placeholder.png)
  </Step>

  <Step title="Choose show or hide">
    Decide whether the element should appear when the condition is true (**Show if**) or disappear when the condition is true (**Hide if**). Most rules are easier to reason about as "show if," but either works.
  </Step>

  <Step title="Save and preview">
    Save the survey and open **Preview**. Answer the source question both ways to confirm the element appears and disappears as expected.

    ![Preview mode showing Q4 visible after answering Yes to Q3, and hidden after answering No](/images/placeholder.png)
  </Step>
</Steps>

## Combining Multiple Conditions

You can add more than one condition to a single visibility rule. When you add multiple conditions, choose whether **all** of them must be true (AND logic) or **any one** of them must be true (OR logic) using the toggle that appears between condition rows.

<Tip>
  Keep visibility rules as simple as possible. A question hidden by display logic still exists in the survey structure. If a respondent never sees it, it will appear as unanswered in your data, which is expected behavior.
</Tip>

## Hiding Options and Grid Rows

To hide an individual answer option, select that option in the builder (click the option text to enter edit mode, then open the Logic tab for the option). The same visibility rule builder appears and works identically.

Grid row visibility works the same way: click the row label, open Logic, and set the condition.

<Note>
  When an option is hidden by display logic, it cannot be selected by the respondent. If carry-forward is also active on that question, hidden options are not carried forward to the next question.
</Note>
